# AI Fridge Meal Planner

CECS 451 team prototype that suggests recipes from ingredients a user has, with optional expiration-date priority, dietary filters, cooking-time limits, ingredient matching, and locally saved meal ratings.

## Run locally

Requirements: Node.js and npm, a Gemini API key, and an internet connection for recipe generation.

1. Follow [API key setup and run instructions](API_KEY_SETUP_RUN.md). The key belongs in `backend/.env`; never commit it.
2. Start the backend and frontend in separate terminals using the commands in that guide.
3. Open `http://localhost:5173`, add ingredients, optionally set expiration dates, choose filters, and select **Generate recipes**.

## How it works

The React app sends ingredient names and optional `YYYY-MM-DD` expiration dates, plus dietary and time filters, to `POST /api/recipes`. The Express backend sends the ingredient data to Gemini using a structured JSON response schema. It validates the returned recipes, applies supported dietary and time checks, matches ingredients, then sorts recipes by soonest upcoming expiration dates used and by number of missing ingredients. The app displays the recipes and can save ratings in that browser's local storage.

## Data and limitations

Ingredient names and expiration dates are manually entered by the user. Recipes are generated by Gemini; the prototype does not use a separate recipe dataset. Expiration dates are optional ranking hints, not food-safety assessments. Dietary checks are basic text checks and cannot establish allergy safety. Recipe times and instructions may be inaccurate, and ratings do not yet change recommendations. Saved meals stay in the current browser and device.

See [architecture and main files](documentation/architecture.md) for the request flow and implementation details.
